# 狮山智生活 — 微信小程序 MVP

这是一个用于需求验证的原生微信小程序演示版，覆盖：

- 校园电话卡套餐选购、在线支付、实名激活与进度展示
- 电瓶车浏览、详情、在线支付与校内配送
- 校园车辆牌照办理辅助：平台购车免费，自带车辆在线收取49元服务费
- 订单列表与基础售后
- 订单页展示售后进度、响应时限和商家处理结果
- 学生身份模拟认证
- 订单、售后与办理数据统一保存到后端数据存储
- 电瓶车库存支持预占、支付扣减、取消释放、退款回补，并在后台留痕库存流水
- 商家可在商品管理页查看本店库存流水，按入库、调整、订单和售后核对库存变化
- 商家商品列表同步展示有效销量与补货提示，平台和商家使用同一套销售口径
- 限时话费福利支持投放期、状态展示和活动订单统计，过期或未开始活动会自动停止下单
- 商品限时特价由服务端校验投放期并生成订单快照，商家分账按实付促销金额计算
- 商家工作台支持自配商品限时特价，投放期与生效价仍由服务端强制校验
- 商家资质被驳回后可上传新执照并申请复审；已入驻商家可在资质到期前提交新执照复审

## 如何运行

### 1. 获取代码（注意子模块）

后端 `server/` 是独立的 git 仓库，已注册为 git 子模块。**必须带 `--recurse-submodules` 克隆**，否则 `server/` 会是空目录、整个后端拿不到：

```bash
git clone --recurse-submodules https://github.com/komorebi-Lee/e-school.git
cd e-school/server && npm install
```

若已经克隆但 `server/` 为空，执行 `git submodule update --init --recursive` 补齐即可。

### 2. 启动后端

```bash
cd server
npm install
npm start
```

默认监听 `http://localhost:3000`；浏览器访问 `http://localhost:3000/admin` 可打开运营管理端。

### 3. 导入小程序

1. 安装并打开微信开发者工具。
2. 选择“导入项目”。
3. 选择本目录 `campus-go-mvp`。
4. AppID 可使用测试号；项目已配置 `touristappid`。
5. 点击编译即可体验。

## 演示范围

当前版本的业务数据统一写入 `server/` 的 JSON/MySQL 存储；本地缓存仅用于商品兜底展示和用户填写信息，不再作为业务订单来源。默认仍使用 `mock` 支付演示；配置完整微信支付商户参数后可启用 JSAPI 支付、服务端查询、支付/退款回调验签和退款，本地关单会同步关闭微信交易，订单超时后收到延迟支付也会自动入账并退款。微信模式还支持下载交易/资金账单并在管理端执行本地对账。校方、实名和运营商接口仍为模拟边界。

后端服务位于 `server/`。小程序商品、下单、支付确认、订单、售后和商家工作台直接调用该服务。使用 Node.js 18+ 进入该目录后运行 `npm install`（安装唯一运行时依赖 `mysql2`）再 `npm start` 即可启动；运行 `npm test` 可执行接口测试。

浏览器跨域默认只允许本地开发地址；如需公网 H5 管理端，请在服务端配置 `CORS_ALLOWED_ORIGINS` 精确来源。

管理端登录已加入防暴力破解：同一来源地址和账号 15 分钟内连续失败 5 次会锁定 15 分钟，防止后台账号被持续撞库；失败锁定状态会持久化，服务重启后不会清零。生产环境推荐使用 `ADMIN_PASSWORD_HASH` 存储 scrypt 哈希，并在 `server/` 内运行 `npm run hash-admin-password` 生成。管理端会话哈希会持久化，服务重启后不需要重新登录。

管理端支持多管理员与基础 RBAC：超级管理员可在「管理员管理」页创建运营、财务、客服角色，编辑账号、停用/启用并重置密码；后端按角色限制商品、订单、商家、财务、系统设置和管理员管理接口，账号停用后现有会话立即失效。

运营设置支持配置变更留痕：每次有效保存都会记录操作者、字段前后值和配置快照，后台可查看最近变更，便于追溯佣金、账期、SLA 等规则调整。财务角色可在「支付单」页按日期执行微信账单对账，查看支付/退款匹配数、差异明细和最近报告；差异会自动生成带时限的平台财务待办，逾期后进入超时预警和运营站内通知，运营可查看逾期状态、认领、留痕处理，重对相符后自动关闭。商家提现确认打款时必须上传平台托管的银行回单，回单 URL 会随提现单和财务流水留档。

服务启动后，在浏览器访问 `http://localhost:3000/admin` 可以打开“狮山智生活”运营管理端。

## 商家资金账户

商家工作台（`pages/merchant/index`）的「资金账户」面板按后端分账状态机展示钱的位置：

`支付成功 → 交付核验 → 账期 → 申请提现 → 平台审核打款`

- 顶部显示可结算余额、平台服务费率与账期天数
- 下方分别列出待交付核验、账期中、已结算，以及仅在有金额时出现的提现待审核、售后冻结与已冲销
- 「最近分账」每条记录标注当前阶段（待交付核验/账期中/可结算/售后冻结/已结算/已冲销）和下一步提示，例如「09/12 后可结算」
- 「申请提现」按钮：可结算金额达到起提门槛且收款账户完整时可点击，确认后提交提现申请；不满足条件时按钮置灰并显示具体原因（金额不足、账户未配置、已有待审核申请）
- 「提现记录」列出最近 3 笔提现单及其状态（待审核/已打款/已驳回/已关闭），驳回会带上平台填写的原因

商家不能自己确认到账，只能提交申请，由平台在管理端「商家提现」页审核后打款。账期天数与起提门槛由管理端运营设置控制，详见 `server/README.md` 的「商家分账与账期」「商家提现申请与平台审核」。

## 履约超时预警

后端内置运营巡检定时任务，按管理端「运营设置」里的时限逐条扫描进行中的业务，把逾期风险变成可认领的预警工单，不再依赖有人打开管理端才发现超时。

`即将超时 → 已超时 → 已认领 → 自动关闭`

- 覆盖订单交付、电话卡激活、话费到账、宽带核验、牌照办理、售后响应、售后解决、提现审核、对账差异处理、咨询线索跟进、商家资质到期共 11 条规则
- 同一轮巡检会关闭超时未支付订单并释放预占库存，不依赖用户继续访问小程序
- 商家分账账期到期后也会由巡检自动推进为可结算，商家提现金额不依赖打开工作台刷新
- 每条规则区分责任方：商家负责交付与售后，平台负责办理类与资金审核
- 业务状态推进后，下一轮巡检会自动关闭对应预警，无需人工销单
- 管理端「超时预警」页展示待处理/已超时/已认领统计、上次巡检时间，可手动触发巡检、认领预警并跳转到对应业务页
- 商家工作台（`pages/merchant/index`）的「履约提醒」卡片展示属于自己的未关闭预警和剩余时间，平台负责的条目不会出现在商家端

规则时限、巡检间隔的具体字段与接口说明见 `server/README.md` 的「运营巡检与超时预警」。

## 商家服务分

平台会根据按时交付、售后响应、售后满意、评价星级和差评处理五个维度计算商家服务分，并把结果用于商品曝光、上新复核和商家整改：正常商家自主经营，限流商家新增商品需平台复核，低分商家暂停上新。商家工作台和商品详情页均会展示服务分，管理端提供人工调分、待复核商品和变更日志。完整规则与接口见 `server/README.md` 的「商家服务分与平台处置」。

## 部署到微信云托管

后端 `server/` 通过微信云托管的**流水线**（绑定 Git 仓库）构建镜像并发布。

### 部署前自检

```bash
cd server
npm run preflight
```

`preflight` 会把「会在云端构建阶段炸掉、但本地毫无征兆」的条件提前查出来
（Dockerfile 位置、npm 源、构建必需文件、锁文件与 `package.json` 是否同步、端口一致性）。
退出码非 0 表示存在阻断项。

### 流水线配置（控制台「服务设置 → 流水线」）

| 配置项 | 应填 | 说明 |
|---|---|---|
| 代码仓库 | **`e-school-server`**（本仓库） | **不要**绑外层仓库 `e-school` |
| 目标目录 | **留空** | 本仓库根目录即代码根目录；填了值会以它为根寻找 Dockerfile，填错即构建失败 |
| DockerFile 文件 | 有，名称 `Dockerfile` | 位于仓库根目录 |
| 端口 | **80** | 必须与 `Dockerfile` 的 `ENV PORT=80` 一致；官方明确「填错会导致版本创建失败」 |

> **为什么不能绑外层仓库**：外层 `e-school` 把 `server/` 登记为 git submodule，
> 而云托管官方文档明确「**微信云托管流水线仅拉取代码不做任何其他操作**」——
> 它**不会**执行 `git submodule update`，因此外层仓库克隆后 `server/` 是**空目录**，构建必然失败。
> `--recurse-submodules` 只影响**本地开发**，对云托管无效。

### 构建环境必须显式更换 npm 源

云托管官方文档《如何提高项目构建效率 → 更换源站》明确：

> 微信云托管线上构建的 Docker 镜像源已经是腾讯加速源了，所以不需要自己设置
> ```dockerfile
> # NPM更换腾讯加速源
> RUN npm config set registry https://mirrors.tencent.com/npm/
> ```

⇒ **基础镜像由平台加速，但 npm 源需要自己换。** `server/Dockerfile` 已设置
`RUN npm config set registry https://mirrors.cloud.tencent.com/npm/`（官方 Express 模板同款）。

本机冷缓存实测（同一份 `package-lock.json`）：

| 源 | 冷缓存安装耗时 |
|---|---|
| `registry.npmjs.org`（npm 官方源） | **约 23.0s** |
| `mirrors.cloud.tencent.com/npm/`（腾讯源） | **约 2.7s** |

约 **9 倍**差距。云端构建环境若访问 npm 官方源受限，`npm ci` 这一步会显著变慢甚至超时，
表现为流水线失败。

### 关于 `cloudbase.yaml`

该文件**不被微信云托管读取** —— 服务名、规格、端口、环境变量均以**控制台**为准，
`cloudbase.yaml` 仅供人工参考，不要以为改了它就能改线上配置。

其中 `DB_FILE` 指向容器内路径 `/app/data/db.json`，但该目录**既不在镜像里、也没有挂载卷**，
**容器重建即丢失全部数据**。生产环境必须挂载持久化卷或改用云数据库（见 `server/README.md`）。

## 正式上线检查清单

从 MVP 演示切到正式运营，按顺序完成以下事项：

1. **小程序主体与类目**：微信公众平台确认小程序为个体工商户/企业主体，电商类目已通过审核；AppID 与 `miniprogram/config/api.js` 的云托管环境保持一致。
2. **云托管环境变量**（微信云托管 → 服务设置 → 环境变量）：
   - `WECHAT_APPID` / `WECHAT_APP_SECRET`（订阅消息与登录能力）
   - `PAYMENT_PROVIDER=wechat` + `WECHAT_PAY_MCHID`、`WECHAT_PAY_SERIAL_NO`、`WECHAT_PAY_PRIVATE_KEY_PATH`、`WECHAT_PAY_APIV3_KEY`、`WECHAT_PAY_NOTIFY_URL`
   - `MYSQL_HOST/PORT/DATABASE/USERNAME/PASSWORD`（持久化）、`ADMIN_PASSWORD_HASH`（生成方式见上文）
3. **微信支付商户号**：商户平台申请 JSAPI 支付并绑定 AppID；回调地址使用云托管内网调用路径，`WECHAT_PAY_NOTIFY_URL` 指向该地址；上线前用 1 分钱真实订单走通支付 → 回调 → 对账。
4. **微信登录**：云托管调用默认注入 openid 头，无需额外证书；若自建域名调用微信接口出现 `self-signed certificate`，需为服务器配置可信证书链，或继续使用云托管默认调用。
5. **隐私与协议**：小程序后台「用户隐私保护指引」中声明手机号、位置、订单信息用途；协议页内容与实际业务一致。
6. **模拟数据清理**：删除或下架种子商品/演示订单；管理后台核对商家资质、话费套餐与真实运营商报价一致。
7. **回归验证**：`cd server && npm test` 全绿；真机体验完整下单 → 支付 → 配送 → 评价 → 售后链路。
